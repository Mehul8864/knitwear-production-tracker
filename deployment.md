# StitchOps — Deployment Guide

**GitHub Repository:** https://github.com/Mehul8864/knitwear-production-tracker

---

## Project Overview

StitchOps is a production order-tracking SaaS for knitwear exporters built with Next.js 16, Supabase, and TypeScript. It connects merchandisers, factory supervisors, and international buyers through a single source of production truth.

---

## Prerequisites

- Node.js 20+ (project was developed on v22.12.0)
- npm 10+ (v11 used in development)
- A Supabase account (free tier works for demo)
- An OpenAI account (optional — only needed for AI features)
- Git

---

## 1. Clone the Repository

```bash
git clone https://github.com/Mehul8864/knitwear-production-tracker.git
cd knitwear-production-tracker
```

---

## 2. Install Dependencies

```bash
npm install
```

---

## 3. Supabase Project Setup

1. Go to https://supabase.com and create a new project
2. Note your **Project URL** and **anon key** (Settings → API)
3. Note your **service role key** (Settings → API → Project API keys)
4. In Supabase dashboard → Storage → Create a bucket named `production-photos`
   - Set bucket to **Public**

---

## 4. Database Migration

In your Supabase project, open the **SQL Editor** and run these files in order:

```
supabase/migrations/001_initial_schema.sql
supabase/migrations/002_rls_policies.sql
supabase/seed.sql
```

---

## 5. Local Environment Setup

Copy the environment template:

```bash
cp .env.example .env.local
```

Edit `.env.local` and fill in your values:

```
NEXT_PUBLIC_SUPABASE_URL=          # Your Supabase project URL
NEXT_PUBLIC_SUPABASE_ANON_KEY=     # Supabase anon key
SUPABASE_SERVICE_ROLE_KEY=         # Supabase service role key (server-side only)
OPENAI_API_KEY=                    # Optional — enables AI features
OPENAI_MODEL=gpt-4o-mini           # Classification model
WHISPER_MODEL=whisper-1            # Transcription model
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

**Environment variables reference:**

| Variable | Required | Description |
|----------|----------|-------------|
| `NEXT_PUBLIC_SUPABASE_URL` | Yes | Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Yes | Supabase anon key (safe for browser) |
| `SUPABASE_SERVICE_ROLE_KEY` | For seed only | Admin key — never expose to browser |
| `OPENAI_API_KEY` | Optional | Enables Tamil translation + classification |
| `OPENAI_MODEL` | No | Default: `gpt-4o-mini` |
| `WHISPER_MODEL` | No | Default: `whisper-1` |
| `NEXT_PUBLIC_APP_URL` | Yes | Base URL for buyer access links |

## 6. Seed Demo Data

```bash
npm run seed
```

This script will:
- Create demo users in Supabase Auth
- Insert buyers, production units, orders, milestones
- Generate 7 days of production history
- Generate buyer access links (printed to console)

---

## 7. Start Local Development

```bash
npm run dev
```

Open http://localhost:3000

---

## 8. Run Tests

```bash
npm test
```

Runs 36 unit tests covering the run-rate engine, utility functions, and AI schema validation.

---

## 9. Production Build

```bash
npm run build
npm run start
```

---

## 10. Deploy to Vercel

1. Push to GitHub
2. Import project at https://vercel.com/new
3. Set all environment variables in Vercel dashboard (Settings → Environment Variables)
4. Deploy — Vercel auto-detects Next.js

---

## 11. Supabase Storage Configuration

After creating the `production-photos` bucket:

1. Go to Storage → Policies
2. Add policy: allow `INSERT` for authenticated users
3. Add policy: allow `SELECT` for authenticated users

---

## 12. AI Configuration

AI features are optional. When `OPENAI_API_KEY` is not set:
- Tamil notes can still be manually categorised
- Voice recording capture still works (transcription is skipped)
- Manual category selection remains available

## Troubleshooting

### "Supabase URL is required"
Make sure `.env.local` has `NEXT_PUBLIC_SUPABASE_URL` set.

### Login fails with placeholder credentials
Run `npm run seed` to create demo users in your Supabase Auth.

### Build fails with "type check" error
Run `npm run type-check` to identify the error. All known type errors are fixed.

### AI classification shows "AI not configured"
Set `OPENAI_API_KEY` in `.env.local`. The app works fully without AI (manual mode).

### Storage upload fails
Check that the `production-photos` bucket exists and storage policies are configured.

### RLS blocking queries
Ensure migration `002_rls_policies.sql` has been applied. Check Supabase logs for policy violations.
